# 移动端优先的口播视频视觉规范

这份规范用于个人 IP 横屏口播、知识解释和产品进度视频。目标不是把所有信息放进画面，而是在手机尺寸和短停留时间里，让观众一眼抓住当前口播要点。

## 一、信息预算：画面只回答一个问题

- 每个语义段只允许一个主结论，最多一个辅助关系。
- 画面展示流程、框架、结构、对比或结果，不展示整段口播稿。
- 详细说明留给口播；字幕负责还原真实口播，不承担额外解释。
- 一个信息栏最多包含：小标签、主标题、副标题。默认禁止解释段落、三行以上 bullet 和密集小字。
- 真实截图只有在口播明确指向它时出现；如果截图里的文字不是当前要点，不为了“完整”而强行展示。

## 二、手机可读性：先按手机验收，再看电脑大屏

以 1920×1080 母版为基准：

- 主标题建议 ≥ 60px；场景标题不得低于 48px。
- 副标题建议 28–36px；普通信息标签建议 ≥ 20px。
- 12–16px 只允许用于品牌角标、编号和非关键技术标识，不能承载结论。
- 单行文字尽量不超过 14 个汉字；需要补充时拆成两级，而不是继续缩小字号。
- 设计阶段必须输出一张缩小到手机观看尺寸的 QA 图（约 390px 宽）并实际阅读；电脑上看不清即判定失败。
- 透明度、阴影和描边只能帮助字读清，不能用来掩盖字号过小或信息过量。

## 三、像 PPT 一样有节奏地出现

- 流程、框架、步骤和对比必须按 1 → 2 → 3 → 4 顺序入场。
- 每个步骤单独出现，建议间隔 0.30–0.60 秒；当前步骤保持可见后再引出下一步。
- 不允许一个时间点把标题、所有节点、所有说明和素材整体同时弹出。
- 入场顺序应遵循：主题结论 → 结构骨架 → 关键节点 → 证据/结果。
- 退出应由场景转换完成；不要在场景结束前把信息提前清空。

## 四、右上角主题牌：语义锚点，不是信息仓库

右上角只承担“这一段现在讲什么 / 得出了什么”的功能：

1. 小标签：阶段或状态，例如 `INPUT LOCKED`、`FIELD TEST`。
2. 主主题：一句可独立理解的结论。
3. 重点词：用品牌色、下划线或手绘圈强调一个词。
4. 短线或节点：只作为当前主题的状态反馈。

禁止把右上角做成固定模板、密集 bullet 列表、常驻雷达或第二套字幕。每个场景必须根据口播更换主题词和视觉隐喻。
默认优先采用透明悬浮排版（胶囊状态标签＋大标题＋短横线＋极短副标题）；只有在语义确实需要承载结构时，才使用轻透明容器。

## 五、人物与素材的优先级

优先级固定为：人物主体 > 当前口播字幕 > 场景主标题 > 主题牌 > 证据素材细节 > 装饰。

- 信息层必须给人物脸和肩部留出稳定缓冲区。
- 素材如果接近人物，先缩窄信息列或改布局，再考虑降低透明度；不能靠加深蒙层解决碰撞。
- 截图的显示策略必须在策略表中登记：整图、局部、静态或仅左右平移。不要为了“看起来更丰富”自动添加缩放。

## 六、改动后的回归门禁

每次收到用户反馈后，先登记问题，再修改。修改完成后必须重新检查：

- 字体大小与手机缩略图可读性；
- 信息密度和是否仍在展示口播之外的内容；
- 主题牌是否与当前语义一致；
- 元素是否按顺序出现而非同时跳出；
- 人物脸、肩、字幕和素材边缘是否安全；
- 上一轮已经修复的问题是否回归。

没有完成这组回归检查，不得把新版本标记为最终交付。
