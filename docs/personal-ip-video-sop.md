# 个人 IP 实拍视频标准生产路径

适用范围：AI 创业日志、Build in Public、产品开发记录、知识型口播与真实产品演示。

这套路径来自早期个人 IP 项目的完整复盘。核心原则不是“尽快进入渲染”，而是先把内容、A-roll 和产品操作的时间线锁定，再进行字幕和视觉包装。

## 默认交付规格

- 主画幅：16:9，1920×1080，30fps。
- 口播节奏：自然偏快；优先通过删停顿和重录解决节奏问题，最终保调加速建议为 1.05–1.12。
- 视频长度：内容说完即结束，不强行凑 30 秒、60 秒或 3 分钟。
- 编码：H.264，CRF 18；音频 AAC 48kHz。
- 音频响度：旁白优先，建议约 -16 LUFS，峰值不高于 -1.5 dBTP。
- 默认保留一份无 BGM 的干净母版，方便在剪映等软件中继续调整音乐。
- 个人 IP / Build in Public 口播线默认不生成开头封面或结尾封面；只有用户明确要求时才启用封面方案。

## 标准路径

### 0. 立项与真实性边界

先生成并确认：

- `director_plan.md`
- `voice_script.md`
- `asset_plan.md`

在拍摄前明确：

- 本期只讲一个核心问题。
- 哪些内容是事实、当前进展、计划和假设。
- 哪些产品功能有真实截图或录屏支撑。
- 哪些隐私字段需要遮挡。
- 最终发布横屏还是竖屏。

检查点：没有素材证明的产品功能、用户反馈、收入和开发过程不得进入脚本。

### 1. 文案口语化与拍摄提纲

文案采用：

`Hook → 背景 → 当前进展 → 真实展示 → 遇到的问题 → 下一步`

拍摄时不要求逐字背稿，但必须保持段落顺序。每段只讲一个意思，段落之间停顿 1–2 秒，便于粗剪。

检查点：

- 前 3 秒的问题或冲突能在正文中兑现。
- 删除发布会语言、广告腔和重复结论。
- 不为了固定时长增加空话。

### 2. 原始素材本地接收与技术检查

直接读取手机原始文件，不用上传后的转码文件代替母版。

必须检查：

- 分辨率、帧率、编码和旋转信息。
- 是否为 HEVC、10-bit、HLG 或 Dolby Vision。
- 音轨是否完整。
- 横竖屏是否符合最终构图。

HDR 素材处理：

- 永久保留原始 MOV。
- 先制作 BT.709 编辑母版或代理文件。
- HLG 素材使用正确线性化和色调映射，不做简单“改标签式”转换。
- 转换后先抽查肤色、黑色衣物、高光和方向，再进入粗剪。

### 3. A-roll 优先粗剪

先只处理人物口播：

- 删除口误、重复拍摄、长停顿和无意义开场。
- 保持语义顺序，不添加字幕、BGM、产品录屏或复杂包装。
- 输出 `a-roll-rough-cut.mp4`。

检查点：

- 从头听一遍，确认内容连贯。
- 在多个原片切换处检查色彩和音量是否一致。
- 全片检查黑帧、异常静音和方向错误。

只有 A-roll 确认后，才进入产品操作录屏。

推荐直接使用本地粗剪入口，不需要 ChatCut 时间线，也不上传原片：

```powershell
npm run factory -- rough-cut --project projects/<episode-id> --action run --input "D:\video\part-01.mov" --model base --layout portrait-left
```

先审核 `rough-cut/cut-list.json` 中的 `review` 项，再运行 `--action master` 输出 1080p 母版。详细规则见 [本地口播粗剪](local-rough-cut.md)。

### 4. 按 A-roll 录制产品操作

播放已确认的 A-roll，边听边录产品操作，尽量让操作顺序与口播一致。

录屏要求：

- 使用真实产品，不生成假 UI。
- 演示数据尽量使用中性测试数据。
- 每个功能开始前停留约 1 秒，结束后再停留约 1 秒。
- 操作节奏略慢于最终观看速度，给后期留出裁切空间。
- 一次只演示一个目标功能。

输出：

- `screen-recording-original.mp4`
- 浏览器兼容的 H.264 代理文件
- 功能与时间段映射表

### 5. 字幕与语义时间线

对确认后的 A-roll 运行本地 Whisper，生成 SRT，并先保存不可覆盖的原始 JSON/SRT。详细门禁见 [口播字幕忠实度标准](transcript-fidelity-standard.md)。

随后人工校正：

- 产品名、人名和品牌名。
- 领域词汇。
- 数字、时间和专有名词。
- 单句断行和标点。

参考文案默认只作 `reference-only`：必须先识别，再回听原声；只有识别不清时才用参考文案缩小候选范围。拍摄者不要求逐字照稿读，因此禁止把参考文案批量覆盖到 Whisper 时间戳上。

任何新增、删除、改句、数字修改或分段合并都必须记录在 `caption-corrections.json`，并标记 `audioVerified: true`。音频无法确认的内容必须保留为 `review`，不能进入最终字幕。

再根据字幕建立：

- 产品录屏语义段。
- 人物主画面段。
- 信息卡片和标注出现点。

原则：字幕、人物和录屏都使用同一条全局时间线；Remotion 分段视频必须传入对应的 `trimBefore`，不得在每个场景重新从素材开头播放。

### 6. 先做 15–30 秒视觉样片

完整渲染前，只选取最复杂的一段做样片，必须同时包含：

- 大尺寸人物。
- 圆形人物蒙版。
- 产品录屏。
- 动态字幕。
- 信息卡片或重点标注。
- 一次版式切换。

样片确认以下事项：

- 人物裁切是否露出模糊延展背景。
- 录屏是否足够大。
- 字幕是否遮挡产品内容。
- 隐私遮罩是否跟随页面滚动。
- 色彩和声音是否正确。
- 版式切换是否自然。

样片未确认，不渲染全片。

样片确认后，不能直接把样片 HTML 当成完整版模板。必须先建立“全片组件回归表”，逐场景列出所有流程类结构（流程框、时间线节点、循环步骤、阶梯、前后对照），并为每组明确：

- 是否同段同时入场，还是有明确的结构性入场节奏。
- 口播 cue 与当前高亮状态的映射。
- 哪些元素是静态设计，哪些元素必须动态高亮。
- 全组可见、第一状态、中间状态和最终状态的验证帧。

只有回归表覆盖全片后，样片规则才算完成迁移；只验证样片对应的一个场景不得进入全片渲染。

### 7. 段落式视觉包装

人物版式由内容段落决定，不由每次抬头或低头决定。

默认规则：

- 观点、解释和情绪表达：大尺寸矩形人物。
- 连续产品操作：录屏为主，人物使用圆形蒙版。
- 同一版式建议至少保持 8–15 秒。
- 短暂低头或抬头不触发切换。
- 大幅重排使用 0.3–0.6 秒的克制遮罩、擦拭或切换，不叠加两套完整布局造成双影。
- 每个产品演示段进入和退出时优先保持矩形布局，避免边界连续跳切。

矩形人物框必须裁进真实画面区域，不能把原始模糊背景一起框入。

### 8. 全片渲染与音频封装

推荐顺序：

1. Remotion 渲染 1920×1080、30fps、H.264 CRF 18 视频。
2. 使用原始 A-roll 音频做保调加速和响度标准化。
3. FFmpeg 复制视频流并封装标准化音轨，避免视频二次编码。
4. 输出无 BGM 母版。
5. 如需系统自动配乐，再输出单独的 BGM 版本。

### 9. 最终验收

技术验收：

- 1920×1080、30fps。
- H.264/AAC、48kHz。
- 时长与音频一致。
- 无持续黑帧。
- 音量峰值和平均响度合格。

内容验收：

- 开头 3 秒能建立问题。
- 全片没有同一素材无意义循环。
- 产品画面都来自真实素材。
- 隐私字段已遮挡。
- 字幕专有名词正确。
- 字幕逐句忠实于实际口播；参考稿介入处、改句处和合并分段处均已回听并有校正记录。
- 人物版式不存在高频跳动。
- 关键切点前后各抽查至少一帧。
- 全片每个流程类组件组都完成 entrance/focus 回归，不得只抽查样片所在场景。

### 10. 发布素材包

成片锁定后再生成：

- `final-clean.mp4`
- 可选 `final-with-bgm.mp4`
- 发布标题
- 作品简介
- 话题标签
- 本期复盘记录

说明：个人 IP 线默认不输出封面文案与封面图；若用户明确要求封面，必须单独确认版式、文字和安全区后再生成。

## 第一期开出的禁止项

- 不用上传平台生成的中间视频替代手机原片。
- 不在确认 A-roll 前录大量产品操作。
- 不把 HDR 素材直接当普通 SDR 处理。
- 不在每个 Remotion `Sequence` 中让人物视频从头播放。
- 不根据每次抬头、低头切换版式。
- 不先渲染三分钟全片再讨论基础版式。
- 不用文件大小判断分辨率或清晰度。
- 不把 BGM 永久压进唯一母版。
- 个人 IP 口播线不默认制作开头/结尾封面，前三秒直接进入 Hook。
