# 视频生产线实战经验库

## 文档定位

这不是理论规范，而是根据本项目已经实际处理过的多轮口播粗剪、Whisper 字幕、Remotion/HyperFrames 包装和三条生产线改造整理出的经验。每条经验都尽量对应一个真实症状、原因、修复方式和以后要执行的门禁。

经验库的作用是减少返工，不替代具体项目的 `storyboard.md`、素材清单、`WORK_PROGRESS.md` 或最终媒体验收。

## 已发生问题与固化经验

| 编号 | 实际问题 | 根因 | 已采取的处理 | 以后固定做法 |
|---|---|---|---|---|
| L01 | 一开始就进入全片包装，后来反复改横竖屏、人物框、录屏和字幕 | A-roll 和产品操作时间线没有先锁定 | 早期项目后把流程改为 A-roll 粗剪 → 按 A-roll 录操作 → 字幕 → 样片 → 全片 | 未确认 A-roll，不录大量操作素材，不渲染全片 |
| L02 | 字幕与口播不一致，出现与实际话语无关的错误文本 | 把用户提供的文案当成字幕源，没有以实际音频为准 | 改为本地 Whisper 实际音频转写，再做领域词校正 | 文案只作审校依据；字幕唯一源必须是实际音频时间轴 |
| L03 | 口播粗剪后仍接近 4 分钟，段内重复和长停顿没有真正切掉 | 早期只检测整段静音，没有用词级时间戳形成真实切点 | `local-rough-cut` 增加段内长停顿压缩、词级重录清理和 `cut-list.json` | 自动删除只限确定性填充词；重复表达和语义不确定项先标 `review` |
| L04 | 自动剪得过头，37 秒附近衔接断裂，“报告”一词被切掉 | 把疑似重复当成确定删除，没有保留语义安全边界 | 恢复被误删内容，改为保守剪辑 | 每次自动删除都要听前后完整句；关键语义词不得跨剪切点 |
| L05 | 大文件转码后人物画面黑白、偏色或黑色衣服发灰 | iPhone 4K 10-bit HEVC 的 HLG/Dolby Vision 被当成普通 SDR 解释 | 使用正确的 HLG 线性化、1000-nit Mobius 色调映射和 BT.709 母版 | 先做 HDR→BT.709 代理并抽查肤色、黑色、高光、方向，再粗剪 |
| L06 | 竖屏转横屏时出现大量黑边、原始背景露出、画面不满框 | 使用 `contain` 或人物框尺寸与源画面比例不匹配 | 按内容采用裁切、受控模糊扩展和真实画面区域裁框 | 人物、录屏、截图分别登记 `cover/contain/crop` 策略；样片先验收安全区 |
| L07 | 大矩形人物和圆形蒙版频繁跳来跳去，切换像抖动 | 按每次抬头/低头触发版式，而不是按内容段落 | 改为段落式版式；缩短低头不触发切换，切点使用 0.3–0.6 秒克制过渡 | 同一版式尽量保持 8–15 秒；人物姿态只作辅助，不作唯一切换条件 |
| L08 | 24 秒附近矩形切圆形时出现连续跳切、双影 | 两套完整布局同时淡化，且切点没有稳定保持时间 | 改为暗色擦拭/受控切换，并先稳定保持矩形布局 | 不叠加两套完整布局做淡化；每个大段只允许一个主版式 |
| L09 | 产品录屏太小、留白多，截图遮住字或三张图挤到标题 | 自动排版没有按素材长宽和文字安全区做视觉审查 | 先做 15–30 秒复杂样片，调整卡片尺寸、间距和素材数量 | 图片/视频必须通过“内容不被遮挡、文字可读、无无意义留白”检查 |
| L10 | 人物动作与口播对不上，人物视频在每个场景又从开头播放 | Remotion 分段没有使用全片时间传入 `trimBefore` | 每段按全局时间轴裁切，保留人物连续动作 | 所有 A-roll、字幕、录屏和信息卡使用同一条全局时间线 |
| L11 | 手机录屏讲到一个功能时，画面没有对应内容或切换太早 | 操作录屏没有在确认 A-roll 后按语义段录制 | 建立主页、出生资料、命盘、合盘、姓名、报告等语义映射 | 先锁口播，再边听边录；每个功能单独映射起止时间 |
| L12 | 专有名词、数字和结尾静音被 Whisper 识别错 | 通用模型对产品领域词和尾部噪声不稳定 | 人工校正领域词，删除尾部幻觉，并抽查关键帧 | 保留 Whisper 原始 JSON/SRT；校正只改权威字幕，不回写用户脚本 |
| L13 | 语速变快后更像 AI，或为了填时长出现机械加速 | 先定固定时长、后强行变速，且预览音色不等于正式 Voice provider | v3 改为文案审校 → 生成旁白 → 读取真实音频时长；速度只做小范围调整 | 优先删废话和停顿；默认保调 1.05–1.12，不能用加速掩盖文案问题 |
| L14 | 本地预览音色与另一条视频差异明显 | 使用的是无密钥 `edge-preview`，不是 Fish Audio/OpenAI 正式音色 | 在进度和产物中明确标注 provider；云端调用默认关闭 | 不把预览音轨描述成正式克隆音；正式发布前记录 provider、voice id 和授权 |
| L15 | 大视频上传慢、失败，外部时间线不可复现 | 把本地剪辑依赖在 ChatCut 上传和云端时间线上 | 建立本地 Whisper + FFmpeg 粗剪链路，不上传原片 | 原始素材本地保留；云端工具只作为可选协作层，不作为唯一时间轴 |
| L16 | 视频清晰度被文件大小误判，或低码率母版不适合继续剪辑 | 只看 MB，没有看编码、分辨率、码率和音频 | 输出 1920×1080、H.264 High、BT.709、48kHz 母版，并用 ffprobe 验收 | 文件大小不是清晰度指标；每次交付必须记录 ffprobe 媒体事实 |
| L17 | HyperFrames 包装通过 lint，但成片仍可能留白或层级拥挤 | 工具检查的是运行时/布局约束，不代替内容构图判断 | 增加复杂段样片、关键帧抽查和真实素材安全区检查 | lint/check 通过只代表技术可运行，不能代替人工视觉验收 |
| L18 | 另一会话已改造的模块被直接当成当前项目已验收 | 跨会话状态没有重新跑入口和门禁 | 当前治理改为“用户报告/待验证”与“本地已验证”分开 | 跨会话变更必须重新跑默认入口、doctor、gate 和媒体验收 |
| L19 | 数字人改造后触发非目标源哈希漂移 | 电影线公共 `Root.tsx` 发生变更，但数字人隔离基线仍是旧值 | 门禁保留失败并报告漂移，没有静默改基线 | 先确认变更归属，再选择恢复旧基线或正式重封；禁止用更新基线掩盖未审查改动 |
| L20 | 停电/重启或多项目并行后容易丢失状态、覆盖产物 | 任务记录、项目输出和治理租约没有统一收口 | 引入项目独立输出、任务租约、单一进度文件和源清单 | 每次任务结束必须更新进度、释放租约、检查租约归零和产物路径 |
| L21 | 个人 IP 视频反复加入开头/结尾封面，挤占黄金前三秒并引入额外版式问题 | 把“发布素材包”中的封面默认项误套到个人 IP 口播线 | 早期项目复盘后用户明确确认个人 IP 线不再制作封面 | 个人 IP 默认无开头封面、无结尾封面，前三秒直接进入 Hook；只有用户明确要求时才单独启用并先做样片 |
| L22 | 真实模型图压住标题，背景仍沿用未获确认的旧风格 | 素材层级与文字安全区没有在完整渲染前锁定；背景参考图没有转成生产约束 | 修订版右移/缩小素材、重做蓝灰六边形背景，并用关键帧和接触表复核 | 每张图片/视频先登记安全区和最大尺寸；背景必须引用已确认的参考风格；样片与全片都检查“素材不遮字、背景不漂移” |
| L23 | 独立视频某轮包装再次出现无背景/近似纯黑的大面积空场，用户明确要求不能再犯 | 背景只是视觉偏好，没有被当作每个场景必须存在的结构层；改版时缺少“背景层存在性”门禁 | 本次独立视频改用深海蓝/暗琥珀网格与语义信息板；用户再次确认“背景缺失”必须记录为回归问题 | 背景层列为必选资产与必验收项：每个场景必须有主题匹配的背景或真实画面；禁止纯黑和无意留白；样片、接触表、最终抽帧三次检查背景是否存在且连续 |
| L24 | Open Design + HyperFrames 样片中人物被做成“背景感”，转场过重，扫描线喧宾夺主 | 全屏暗洗、渐变擦除和扫描线被误当成科技感主视觉；没有把原视频曝光和真实人物主体性设为硬门禁 | A/B 样片恢复原视频亮度，保留局部蓝/琥珀氛围，移除全屏渐变转场和扫描线，并通过 lint/check 与关键帧复核 | 个人 IP 横屏口播默认继承 `docs/approved-visual-baseline.md`：原视频亮度、背景必在、无扫描线、无全屏渐变转场、素材不遮脸/遮字；任何新风格先独立做样片 |
| L25 | 已批准的样片规则只在完整版一个场景生效，其他流程框仍是旧逻辑 | 样片被当成局部手写实现，未建立全片流程组件清单、统一 focus mapping 和逐组回归 QA | 记录为交付后事故；不重做当期成片，但把规则抽象和全片门禁写入项目日志与 SOP | 样片批准后先枚举全片所有 `step-box / node / loop-box / stage / comparison`；每组明确 entrance、cue、focus、验证帧；没有逐组通过不得标记 final |

## 已验证的默认生产顺序

```text
主题与真实性边界
  ↓
文案审校（只保留可兑现内容）
  ↓
原始媒体技术检查（编码 / HDR / 音轨 / 方向）
  ↓
A-roll 本地粗剪与人工审核
  ↓
按确认后的 A-roll 录制产品操作
  ↓
Whisper 独立转写 → 疑点回听 → 参考稿有限对照 → 字幕忠实度门禁
  ↓
语义分镜与素材时间映射
  ↓
15–30 秒复杂视觉样片
  ↓
Remotion / HyperFrames 全片包装
  ↓
FFmpeg 音频与封装
  ↓
关键帧、字幕、色彩、音频、ffprobe QA
  ↓
无 BGM 母版 → 可选 BGM 版 → 发布素材包
```

## 下一次开工的最小检查表

### 开工前

- 项目属于哪条生产线，输出根目录是否独立。
- 本期唯一核心问题是什么，哪些内容有真实素材支撑。
- 原片是否 HDR/HEVC，最终横屏还是竖屏。
- 文案是否已经口语化，是否存在必须遮挡的隐私字段。

### 进入包装前

- A-roll 是否已经从头听完并确认语义顺序。
- `cut-list.json` 的 `review` 项是否人工处理。
- Whisper 是否针对最终 A-roll 实际音频运行。
- 原始 Whisper 是否保留；参考稿介入、改句和合并分段是否逐条回听并写入校正记录。
- 产品录屏是否有功能—时间段映射。
- 15–30 秒样片是否通过画面填充、字幕安全区和版式切换检查。
- 每个场景是否明确登记背景来源、覆盖范围和最低不透明度；不得出现纯黑底、默认黑画布或无意的大面积空场。

### 交付前

- 关键切点前后是否各抽查一帧，是否有重复循环或突然跳切。
- 产品截图/录屏文字是否可读且没有被卡片、字幕或标注遮挡。
- 是否存在持续黑帧、偏色、异常静音、非预期裁切。
- 背景层是否在开头、主体段落、转场和结尾均存在；若使用真实画面铺底，是否有受控模糊/调色而非裸露黑边。
- 字幕是否来自实际音频，专有名词、数字和结尾是否复核。
- `caption-fidelity-report.md` 是否通过；不得把“时间戳来自 Whisper”误写成“字幕文字来自真实口播”。
- `ffprobe` 是否记录真实时长、分辨率、帧率、编码、音轨和文件大小。
- 是否输出无 BGM 干净母版，是否明确当前是“本地已验证，未发布”。

## 暂未解决或需要人工决策的问题

- 语义重复和“哪句更好”不能安全地完全自动化，必须保留 `review`。
- 数字人 Fish Audio/HeyGen 云端端到端仍需要用户授权、凭据和成本上限。
- `digital-human-isolation` 的 `Root.tsx` 基线漂移需要确认归属后才能正式重封。
- 传播效果、平台流量和标题表现不能从本地渲染门禁推断，必须以发布后的平台数据另行记录。

## L35 事故记录：经验文档存在，但往期视觉风格没有被强制加载

### 现象

前几期已经稳定的大字幕、关键词高亮、旁白加载式入场和素材错峰，在新一期中回退成小字幕、静态文字或普通切画面；制作过程中虽然有经验文档，但没有在开工时形成可验证的加载记录。

### 根因

经验库、视觉基线和项目 `DESIGN.md` 没有唯一优先级；通用“流程框整体出现再高亮”的规则还可以覆盖用户已经确认的往期风格。文档是说明文字，没有项目级上下文哈希和渲染前门禁，导致样片局部修复也没有自动继承到全片。

### 固化门禁

1. 每个视频任务开始前必须读取 `references/iteration-system.md`、历史经验库、视觉基线和字幕标准，并运行 `scripts/iteration_preflight.py --phase start`。
2. 项目必须登记 `iteration-system: loaded` 与 `style-profile: previous-editorial-v1`；渲染前运行 `--phase render`，检查规则哈希没有过期。
3. `previous-editorial-v1` 固定大字幕、关键词高亮、旁白顺序加载、素材错峰和连续蒙版；项目不能用通用默认值静默覆盖。
4. QA 必须保存首个/中间/最终加载状态、字幕高亮、素材转场和安全区关键帧；缺少回归证据不得标记 `final`。

## L36 经验固化：蒙版的居中、同步与连续性

### 观察

本期曾出现蒙版人物偏移、顶部黑边和高频跳动。原因分别是裁切基准没有以鼻子/脸部为圆心、内部视频没有从容器顶端归零，以及 60fps 源片在 30fps 输出中由两个 HTML video 并行解码导致异步取帧。

### 固化规则

使用人物蒙版时必须登记 `mask-profile: centered-nose-shadow-only`：人物鼻子对准圆心；默认只保留柔和阴影，不加黄色/青色圆环；内部视频顶端归零并裁切在容器内；全屏与蒙版使用同一条逐帧同步视频源；素材段及转场期间蒙版持续存在。交付前抽查至少 3 帧连续画面，确认无抖动、双影或黑边。

## L37 经验固化：三步 Hook 的“结构先行、焦点跟随”节奏

### 观察

用户确认的有效片段不是简单的三张卡逐个弹出，而是先让观众理解完整结构，再随着旁白把当前步骤放大、变黄并同步字幕关键词；非当前项仍保留在画面中，形成稳定的阅读锚点。

### 固化规则

遇到三步或多步并列口播，项目必须登记 `rhythm-profile: hook-structure-focus-v1`，执行“整体骨架 → cue 驱动焦点 → 关键词同步 → 保持同版式”的节奏，并抽查首个/中间/最终焦点。通用 `stagger` 只能作为实现手段，不能替代这个语义模板。

## L38 经验固化：往期版式锚点不能只写成“风格像”

### 现象

昨天版本虽然继承了颜色、字体家族和动效语法，但主标题、信息栏和字幕相对往期整体上移/右移，字幕安全带也变高；同一套个人 IP 看起来像换了一套版式。

### 根因

经验文档只记录了色彩、字号区间和语义规则，没有记录可回归的几何锚点。新项目因此把“左侧信息栏”重新解释成自由布局，加入或隐藏眉标时又改变了主标题的 y 坐标。

### 固化门禁

1. 新项目必须登记 `layout-profile: previous-editorial-v1-layout`，按 1920×1080 基准记录主标题、信息栏、主题牌和字幕安全带的 x/y/字号。
2. 16:9 尺寸默认等比换算；用户红框或明确位置高于 profile，不能由执行层用审美覆盖。
3. QA 至少抽查开头、信息段和结尾三个 settled frame，记录实际偏差；未经解释的超过约 4% 偏差不得标记 `final`。

## 经验使用规则

以后新项目不复制整段历史，而是：

1. 先选择生产线和适用条目。
2. 在项目 `WORK_PROGRESS.md` 或任务记录中引用对应经验编号。
3. 如果出现新问题，补充“症状—原因—处理—固定门禁”，通过测试后再写入本文件。
4. 如果经验与新项目实际冲突，以真实素材、媒体验收和用户确认结果为准，并记录取代关系。

## 三层流水线断裂事故记录

### 现象

某次交付文件看起来是“有卡片、有放大镜”的视频，但实际只由 Remotion 组件完成。Open Design 只写进了文档，HyperFrames 没有 HTML 源文件，也没有 `lint`、`inspect`、animation map 或 HyperFrames render 记录，因此动态编排没有真正进入成片。

### 根因

把“沿用某套视觉规则”误当成“已经运行对应工具链”。功能性验证（素材时间对齐、截图出现、字幕显示）被误标成最终视觉验收，导致静态卡片和轻微缩放冒充了 Remotion + HyperFrames + Open Design 成片。

### 固化门禁

以后每条需要三层视觉流水线的视频，必须同时存在并验收：

1. Open Design：项目 `DESIGN.md`，明确版式、颜色、动效节奏和禁用项。
2. HyperFrames：独立 `hyperframes/index.html`，所有动态元素使用 `data-*` 时间属性并注册 `window.__timelines`；必须有 `lint`、`inspect`、animation map 结果。
3. Remotion：最终合成组件实际读取 HyperFrames 输出，并通过 `npm run build` 与关键帧截图验收。
4. 交付前：保存 3 个关键段落样片和完整片 `ffprobe` 信息；没有上述证据不得写 `final`，只能写 `preview`。

本次旧文件保留为功能预览，不覆盖；重做版本单独输出并与旧版对比。

## 样片与正式片不是同一条合成链

### 现象

本次先做出的 10 秒 Open Design + HyperFrames 样片具备明确的 HUD、雷达和节点动画，但后续实际生产片又退回到原始 A-roll 或只用 Remotion 静态层，用户看到的样片和正式输出不是同一个视觉结果；同时工作重点错误地集中在三张证据图的局部调整上。

### 根因

没有在“样片通过”后锁定可复用的视觉源文件和唯一渲染入口，样片只被当成参考图，没有被当成生产基线；另外没有把 HyperFrames 输出复制为 Remotion 的输入资产并在终版前验证来源。

### 固化门禁

1. 样片通过后，必须冻结 `DESIGN.md`、HyperFrames `index.html` 和 Remotion 组合 ID；全片只能从这三者生成，不能重新手工拼一套近似版本。
2. 项目必须保留“样片源 → HyperFrames 预览 → Remotion 终版”的文件链和路径，终版组件必须明确读取 HyperFrames 的渲染文件。
3. 三张证据图仅作为语义段落的单张辅助素材；先验收整条视觉系统，再调素材位置，禁止把局部图片修改当作全片重做。
4. 交付前抽查开头、普通信息段、三个证据段和结尾，并记录每个抽帧的实际产物路径；若抽帧仍是原始 A-roll，立即判定流水线断裂，不得交付。

### 本次修复

将 Open Design 样片重构为正式 HyperFrames 时间轴，重新渲染 HyperFrames 预览，再由正式合成组件读取该文件并叠加 Whisper 字幕，最终输出成片。同时将代理素材重编码为每秒关键帧，避免长 GOP 导致 HyperFrames 在后段跳转卡死。

## 把 Open Design 错当固定图形模板

### 现象

某次 v2 虽然已经把 HyperFrames 接回成片，但把认可样片里的 `TOPIC` 雷达圈机械扩展成长期常驻图层；雷达在对应信息为空时仍然显示。普通信息段持续复用相似的大面板，证据截图又被反复放大和包装，导致装饰脱离当下口播语义，真实人物和论证反而退居其次。技术 lint、check 与媒体规格全部通过，最终画面仍被判定为不合格。

### 根因

1. 把 Open Design 理解成一组可复制的固定图形，而不是“根据每段真实内容选择信息结构和视觉隐喻”。
2. 把统一性错误地落实为常驻雷达、常驻标题和重复面板，而没有只统一字体、色彩、线条、间距与动效语法。
3. 把三张证据截图当成全片设计中心，没有先完成整条口播的逐段语义分镜。
4. 只记录了技术 QA 和少量功能抽帧，没有在全片渲染前用多语义关键帧做人工审美裁决。

### 固化门禁

1. 写任何 HTML/Remotion 视觉层前，必须先提交“逐段内容—视觉策略表”；每段写清楚当前口播、信息结构、视觉隐喻、出现原因和退出时间。
2. 常驻元素白名单默认为空。任何装饰若不能直接解释当前一句口播，必须退出；认可样片中的具体图形不得自动升级为全片模板。
3. 统一性只由设计 token 和运动语法提供：字体、色板、线宽、圆角、间距、安全区、入场节奏；具体版式必须随语义改变。
4. 证据素材只在证据口播段出现，一次一张。先展示完整证据，再用素材自身的推镜/裁切聚焦关键数据；禁止圆形放大镜、调试框和反复堆叠。
5. 全片渲染前必须先保存至少三类不同语义场景的关键帧或短样片，覆盖“观点/数据关系/真实证据”；人工逐项检查人物主体性、语义匹配、可读性、透明度、脸部与字幕安全区。
6. `lint/check/inspect` 通过只表示运行时和布局约束通过；没有人工视觉 QA 结论，不得进入全片渲染，不得标记 `final`。

### 修复方式

重做版本不读取失败成片。新的语义表把全片拆为价格、算账、客户样本、市场比例、专业工作链、方法论转折、验证结果、证据素材和 CTA；每种视觉只在对应语义存在。证据素材改为通透大图、克制推镜和关键区域框选。

## L28 事故记录：信息栏变成说明书

### 现象

画面试图把口播、截图细节、解释段落和额外补充全部展示出来，导致信息栏充满密集小字。电脑上已经难以阅读，缩小到抖音手机观看尺寸后更无法理解；画面重心从“听讲解、看结构”变成“阅读一张缩小的说明书”。

### 根因

把信息完整误当成信息有效，把参考文案误当成画面文案；没有为每段设置明确的信息预算，也没有把“流程、框架、结构、结果”与“详细解释”分开。

### 固化门禁

1. 每个语义段只保留一个主结论和一个辅助关系；详细解释交给口播。
2. 信息栏默认只允许小标签、主标题、副标题；禁止解释段落和密集 bullet。
3. 1920×1080 母版必须通过 390px 宽手机缩略图阅读测试；电脑看不清即不得进入全片渲染。
4. 任何截图只展示当前口播指向的结构或结果，不以“完整展示所有文字”为目标。

## L29 事故记录：所有信息同时跳出

### 现象

流程卡、编号、标题、素材和说明在同一时刻整体出现，虽然技术上有动画，观感却像一次性切入的静态面板，没有参考视频那种 1、2、3、4 的阅读节奏。

### 根因

把“有 GSAP tween”误当成“有信息节奏”；没有把结构拆成可顺序阅读的层级，也没有给每一步设置单独的入场窗口。

### 固化门禁

1. 流程和框架必须按 1 → 2 → 3 → 4 顺序入场，步骤间隔 0.30–0.60 秒。
2. 入场顺序固定为：主题结论 → 结构骨架 → 关键节点 → 证据/结果。
3. 关键帧 QA 必须至少抽查首个节点、中间节点和最终节点，确认不是全部同时可见。

## L30 事故记录：修复一个问题又让旧问题回归

### 现象

用户要求改字体后，信息密度或人物遮挡回归；要求移开素材后，标题层级又变小；同类问题在不同版本反复出现。

### 根因

反馈只作为当前轮次的局部修改，没有进入全局设计规范、项目设计文件和回归检查表；每次只验证“本次修改点”，没有重新检查已修复的问题。

### 固化门禁

1. 所有用户反馈必须同时写入全局规范、项目 `DESIGN.md` 和项目 `USER_FEEDBACK_LOG.md`。
2. 每条反馈必须包含：问题、根因、设计规则、验证关键帧和当前状态。
3. 每次改动后必须重跑字体/密度、语义主题、顺序入场、人物安全区和上一轮回归项。
4. 只有回归矩阵全部通过，版本才允许标记为 `final`。

## L31 事故记录：字体大小没有形成硬性 token

### 现象

每轮都需要重新提醒“字太小”，因为字号随局部卡片变化，没有统一的移动端最低字号和手机缩略图验收。

### 根因

字号被当成局部排版偏好，而不是传播媒介约束；技术 lint 不会判断手机端的真实阅读体验。

### 固化门禁

1. 主标题 ≥ 60px，场景标题 ≥ 48px，副标题 ≥ 28px，关键标签 ≥ 20px；低于 16px 的文字不得承载信息。
2. 每个样片和全片 QA 都要保存手机缩略图，并实际阅读主标题、副标题和主题牌。
3. 如果内容放不下，先删信息、拆层级或改结构，禁止继续缩小字体。

## L32 视觉标准封存：主题牌从容器化回到悬浮语义字

### 结论

某次 20 秒批准样片确认：右上角主题的最佳默认形态不是一个承载信息的矩形框，而是参考图式的透明悬浮字——胶囊状态标签、大标题、短横线和极短副标题。容器只在语义确实需要结构承载时使用。

### 固化门禁

1. 新项目默认引用 `docs/approved-visual-standard.md`，右上角先按悬浮语义字设计。
2. 主题牌必须随口播语义变化，不能成为常驻装饰或第二套字幕。
3. 若确需矩形容器，必须在逐段视觉策略表中说明承载的结构关系，并通过手机缩略图和人物安全区回归。

## L33 事故记录：只保留 Whisper 时间轴，字幕文字被参考稿覆盖

### 现象

某次项目的字幕时间基本来自 Whisper，但最终文字被按用户提供的参考文案大量替换和重写。拍摄时并非逐字照稿，因此成片字幕与真实口播存在偏差；项目 QA 却把“Whisper 时间线”误记成了“真实 Whisper 字幕”。

### 根因

1. 原始 Whisper 质量较差，出现乱码和大量同音词错误，校正时把参考稿错误地升级为权威逐字稿。
2. 没有区分“时间戳来源”和“字幕文字来源”。
3. 没有保存逐条校正原因，也没有对改句、补句和分段合并强制回听。
4. 视觉 QA 和技术 QA 都通过了，但缺少字幕忠实度 QA。

### 固化门禁

1. 先对最终 A-roll 独立运行 Whisper，原始 JSON/SRT 永久保留，不用参考稿预填字幕。
2. 参考稿默认标记为 `reference-only`；只有识别不清时才查看，最终文字必须由原声支持。
3. 繁简转换、标点和断行之外的修改全部进入 `caption-corrections.json`；改句、增删、数字和分段合并必须 `audioVerified: true`。
4. Whisper 为空或仍听不清时标记 `review`，不得直接抄参考稿，不得进入 `final`。
5. 项目必须生成 `caption-fidelity-report.md`，分别说明时间戳来源、文字来源、参考稿介入点和回听范围。
6. 执行标准统一引用 `docs/transcript-fidelity-standard.md`；忠实度门禁未通过时，即使画面和技术 QA 通过也不得交付。

## L25 事故记录：样片规则没有全片化

### 现象

某次 20 秒样片已经验证“流程框同段出现、口播到哪一步哪一框高亮”，但完整版只有一个场景的三个 `step-box` 使用了这套逻辑；其他时间线节点、循环框、阶梯等仍沿用旧的静态 `pick` 或通用 `stagger`。用户看到的结果就是“只改了一个地方”。

### 根因

样片确认后直接在完整版 HTML 上局部手写 `focusCard('#step1'...)`，没有先盘点全片所有“流程类信息结构”，也没有把 entrance 和 focus state 抽象成可复用的数据配置。全片 QA 抽查了几个时间点，却没有按组件组逐一验证规则是否落地。

### 固化门禁

1. 样片批准后先产出全片“语义组件清单”，逐场景枚举 `step-box / node / loop-box / stage / comparison`。
2. 每个组件组必须登记：入场方式、是否全组同时出现、口播 cue、focus 状态、验证帧；静态组必须显式标注 `static-by-design`。
3. 动画必须由统一配置或可复用组件生成，禁止只给样片里的几个手写 ID 加规则。
4. 全片渲染前做静态审计和逐组关键帧回归：每组至少检查全部可见、第一状态、中间状态和最终状态。
5. 只有组件清单、静态审计、逐组人工 QA 全部通过，才能把“样片规则已应用”写入 `final`。

## L34 事故记录：粗剪没有先用字幕做重复审计，结尾缓冲被吃掉

### 现象

粗剪成片仍出现重复表达；结尾最后一个字说完就立即断掉，观感像被硬切。

### 根因

1. 只看剪辑片段或参考文案，没有把“本轮视频 → Whisper 字幕 → 重复审计”作为粗剪前置步骤。
2. 重复句可能是长句中的局部重复，单纯比较相邻整段文本会漏检。
3. 粗剪范围只包到最后一个语音段，未显式保留源视频尾部缓冲。

### 固化门禁

1. 每次粗剪先对实际视频生成字幕，并输出 `repeat-audit.json/.md`；审计覆盖整句重复、长句内重复和近似重录。
2. 候选重复默认标记 `review`，人工回听确认后优先保留后一句，不把参考文案当剪辑依据。
3. `local-rough-cut` 默认使用 `--final-tail-buffer 0.5`，在最后一句后保留约 0.5 秒源尾巴；源尾不足时按实际长度保留。
4. 粗剪后重新转写或核对 source→cut 映射，并在 QA 中记录重复审计结果、结尾时长和听感检查。
