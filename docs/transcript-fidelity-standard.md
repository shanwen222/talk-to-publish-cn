# 口播字幕忠实度标准

适用范围：所有真人口播、访谈、课程、产品讲解和以真实录音为字幕来源的视频。

## 唯一原则

字幕的文字权威源是最终 A-roll 的实际声音。用户提供的文案、提纲和参考稿默认都是 `reference-only`：它们可以帮助判断专有名词和识别不清的词，但不能替代实际口播，也不能因为“写得更顺”就改成稿件原句。

必须区分两件事：

- Whisper 时间戳来自真实音频，不代表字幕文字也忠实于真实音频。
- 字幕与参考稿一致，不代表字幕与口播一致。

## 强制执行顺序

1. **独立识别**：先对最终 A-roll 运行 Whisper，不把参考稿预填成字幕，保存不可覆盖的原始结果。
2. **标记疑点**：只标记乱码、低置信度、同音词、领域词、数字、人名、品牌名和断句问题。
3. **回听原声**：对疑点按原时间段回听；必要时降速、放大音量或换更高精度模型复核。
4. **有限对照**：只有回听仍不确定时才查看参考稿，用它缩小候选范围；最终文字仍必须得到音频支持。
5. **记录校正**：每一处非格式性修改都记录原识别、最终字幕、原因和是否回听。
6. **忠实度 QA**：通过后才允许字幕进入 Remotion、HyperFrames 或最终导出。

## 允许与禁止

无需改变语义即可直接处理：

- 繁体转简体。
- 标点、空格和手机端断行。
- 已由音频清楚支持的同音错字。

以下修改必须回听并记录 `audioVerified: true`：

- 新增、删除或替换任何实词。
- 把一句话改得更顺、更完整或更像参考稿。
- 合并或拆分 Whisper 分段。
- 修改数字、时间、否定词、程度词、因果关系和专有名词。
- Whisper 为空、乱码或无法识别时用参考稿提出候选文字。

明确禁止：

- 按参考稿批量覆盖 Whisper 文本。
- 只保留 Whisper 时间戳，却把参考稿当作字幕正文。
- 因为参考稿表达更好而替换口播中的真实说法。
- 音频无法确认时直接采用参考稿；此类字幕必须标记 `review`，不能进入 `final`。

## 项目必须保留的证据

```text
projects/<episode-id>/subtitle/
├── transcript-whisper.raw.json       # 原始识别，不覆盖
├── captions.review.json              # 待审字幕
├── caption-corrections.json          # 校正审计记录
└── caption-fidelity-report.md         # 忠实度 QA 结论
```

`caption-corrections.json` 每条至少包含：

```json
{
  "start": 23.64,
  "end": 26.32,
  "whisper": "原始识别",
  "final": "最终字幕",
  "reason": "proper_noun | clear_asr_error | segmentation | uncertain",
  "referenceConsulted": true,
  "audioVerified": true
}
```

## 最终门禁

交付前必须同时满足：

- 原始 Whisper 文件存在且未被覆盖。
- 所有非格式性修改都有校正记录。
- 所有语义修改和分段合并均为 `audioVerified: true`。
- 第一段、中间段、结尾段各连续回听至少 20 秒。
- 所有低置信度、空识别、数字、专有名词和参考稿介入处全部回听。
- `QA.md` 分别写明“时间戳来源”和“文字来源”，禁止笼统写“真实 Whisper 字幕”。

任一项未满足，只能标记为 `caption-review` 或 `preview`，不得标记 `final`。
